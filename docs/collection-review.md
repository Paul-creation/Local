# 새 게임 수집 기준 점검 (2026-10-04)

계기: 하데스 2, 할로우 나이트: 실크송(둘 다 2025년 9월 출시, 2025 TGA 올해의 게임 후보)이 DB에 없음.
범위: 코드만 읽고 정리함. DB·스팀 API는 이 점검에서 조회하지 않았음(작업 환경에서 외부 접속이 막혀 있었음). 숫자 추정은 아래 근거로 계산한 대략값.

## 1. 지금 수집 기준

매주 금요일 새벽 2시(KST) `weekly.yml` → `run-steps.mjs weekly`에서 새 게임을 넣는 단계는 두 개.

### `scripts/bulk-import.mjs` (스팀, 사실상 유일한 자동 수집)

| 항목 | 기준 |
|---|---|
| 후보 목록 | 스팀 검색 **한국 최고 판매(topsellers, cc=kr)** 목록을 1페이지(50개)부터 차례로 |
| 1회 상한 | **새 게임 200개를 넣으면 멈춤** (`MAX_NEW_GAMES = 200`) — 매번 1페이지부터 다시 시작 |
| 제외 | 이미 있는 게임, `delisted_appids`에 있는 게임 |
| 출시일 | 2013년 이전 출시작 제외 (출시일을 못 읽으면 통과) |
| 종류 | 스팀 `type`이 `game`인 것만 (DLC·사운드트랙 제외) |
| 장르 | 성인·영상 편집 등 제외 장르, 게임 장르 없이 소프트웨어 장르만 있는 프로그램 제외 (`scripts/lib/non-game.mjs`) |
| 리뷰 | **전체 리뷰 1,000개 이상 + 긍정 65% 이상** |
| 멀티 여부 | **보지 않음** (싱글 게임도 수집) |
| 동접자·가격 | **보지 않음** (동접자는 수집 뒤 `enrich-players`가 채움) |

### `scripts/import-other-stores.mjs`

라이엇·블리자드·에픽 독점작은 코드 안 수동 목록, 에픽은 무료/할인 프로모션 피드. 스팀 게임 수집과는 무관.

### 그 뒤 단계 (게임을 빼는 쪽)

- `check-delisted`: 판매 중단 후보를 **출력만** 함 (삭제·`delisted_appids` 추가는 사람이 SQL로).
- `find-non-games`: 최근 14일 추가분 중 프로그램을 **출력만** 함 (`--hide`일 때만 `hidden = true`로 숨김, 행은 지우지 않음).
- 싱글 게임을 자동으로 지우는 단계는 없음.

## 2. 두 게임이 빠졌을 가장 그럴듯한 원인

두 게임 모두 리뷰 수(수만 개)·긍정률(90%대)·출시 연도·종류·장르 기준은 넉넉히 통과하므로, **필터 때문이 아니라 후보 목록에 오르지 못한 것**으로 보임.

1. **(가장 유력) "지금 잘 팔리는 순위"만 보고, 200개 상한 때문에 깊이 내려가지 못함.**
   - 후보가 그 주의 판매 순위뿐이라, 출시 직후에 수집이 돌지 않았으면 대작도 시간이 지나 순위가 내려가면 다시 볼 기회가 없음.
   - 저장소 기록은 2026-10-02부터 시작되고, 지금 게임 수는 606개(스팀 외 수동 목록 포함). 200개 상한으로 몇 번 돌았다고 보면 지금까지 훑은 깊이는 판매 순위 대략 **상위 600~1,000위**(이미 있는 게임·DLC·필터 탈락분 포함).
   - 두 게임은 2025년 9월 출시라 2026년 10월에는 출시 1년이 넘었음. 출시 효과가 끝난 1인용 인디라 한국 판매 순위에서 그 깊이보다 아래에 있을 가능성이 큼. 반대로 2026년 출시작(114개)·2025년 출시작(93개)이 많은 것도 "최근 판매 순위 기준"과 맞음.
2. **(가능성 있음) 스팀 요청 제한으로 조용히 건너뜀.**
   - `bulk-import`는 다른 스크립트가 쓰는 `scripts/lib/steam.mjs`의 재시도 헬퍼를 쓰지 않음. 429(요청 제한)이면 `appdetails`가 실패한 것으로 보고 그냥 넘어감 → 그 주에는 빠지고, 다음 주 순위가 내려가 있으면 다시 안 잡힘.
   - 리뷰 요청(`appreviews`)은 `try` 밖이라, 제한에 걸려 HTML이 오면 `json()`에서 예외가 나 **스크립트 전체가 중간에 멈출 수 있음**. 이러면 그 주 수집이 200개를 못 채우고 끝남.
3. (가능성 낮음) `delisted_appids`에 잘못 들어간 경우. 수동 SQL로만 들어가므로, 확인하려면 Supabase에서 `select * from delisted_appids where steam_appid in ('1145350','1030300');` (하데스 2: 1145350, 실크송: 1030300) 한 번 실행해 보면 됨.

## 3. 고치는 방안 (코드는 아직 안 고침)

추정 근거: 스팀 한국 판매 순위에서 이미 DB에 있거나 DLC·번들·필터 탈락인 비율을 50~60%로 가정. 실제 수는 미리보기 모드로 한 번 돌려 보면 정확히 나옴.

### 방안 A — 후보 목록 넓히기: "올해·작년 최고 판매작" 목록 추가 (추천)

- 스팀 검색에 출시 연도 범위를 붙인 최고 판매 목록(예: 2025년·2026년 출시작, 각 상위 300위)을 후보에 더함. 출시 시기와 관계없이 "그 해 잘 팔린 게임"이 들어옴.
- 기존 리뷰 1,000개·긍정 65% 기준은 그대로 두어 품질 유지.
- **예상 증가: 1회성으로 약 150~250개**, 이후 매주 0~10개.
- 하데스 2·실크송처럼 출시 1년 된 대작을 잡는 데 가장 직접적.

### 방안 B — 동접자 기준 목록 추가: 스팀 "최다 플레이" 상위 100~250

- 스팀 공식 차트(가장 많이 플레이 중인 게임) 상위 N개를 후보에 더함. 무료 게임·장수 멀티 게임이 잘 잡힘(친구랑 할 게임 찾기라는 사이트 목적과 맞음).
- **예상 증가: 1회성으로 약 30~80개** (상위권은 이미 많이 들어와 있음), 이후 매주 0~5개.
- 단점: 1인용 대작(하데스 2·실크송)은 동접자 순위에서는 잘 안 잡힘.

### 방안 C — 꼭 넣을 게임 목록(수동) + 수집 안정화

- `data/meta/must-have.json` 같은 파일에 GOTY 후보작 등 꼭 있어야 할 스팀 appid를 적어 두면 순위와 상관없이 같은 필터로 넣음. `data/meta/goty.json` 작업과 이어서 쓸 수 있음.
- 같이 할 일: `bulk-import`에서 `steamGet`(재시도 헬퍼) 쓰기, 리뷰 요청 예외 처리. 이건 게임 수를 늘리기보다 매주 수집이 중간에 멈추지 않게 하는 수정.
- **예상 증가: 목록에 적은 만큼 (처음엔 10~30개)**.

### 참고: 상한(200개)만 올리는 방법

- 상한만 올리면 판매 순위를 더 깊이 훑지만, 깊이 내려갈수록 리뷰 기준 통과율이 떨어지고 스팀 요청 제한·단계 시간 제한(45분)에 걸리기 쉬움. 위 방안보다 효율이 낮음.

## 4. 권장 순서

1. 위 SQL로 `delisted_appids`를 확인 (원인 3 배제).
2. 방안 C의 안정화 부분 (재시도 헬퍼·예외 처리) — 작은 수정, 위험 낮음.
3. 방안 A를 미리보기 옵션과 함께 추가해서 실제 늘어날 수를 확인한 뒤 반영.
