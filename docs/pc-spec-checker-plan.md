# PC 사양 체커 조사·설계안

작성: 2026-10-05 · 코드 변경 없음 (조사·설계만) · 기준: 노출 게임 643개 (전체 666개 − 숨김·메인 제외 23개)

목표: 사용자가 자기 PC 사양(CPU·GPU·RAM)을 넣으면 게임별로 **최소 사양 충족 / 권장 사양 충족 / 부족**을 보여준다.

## 0. 한 줄 결론

- **데이터는 충분하다.** 최소 사양은 642개, 권장 사양은 561개 게임에 있다. 다만 전부 "텍스트 한 덩어리"이고 파싱된 필드가 없다.
- **정규식 + 사전으로 CPU·GPU 모델을 인식할 수 있는 비율은 약 78~79%** (최소 사양 기준). 모호하지만 "저사양"으로 볼 수 있는 표기(GHz만, DirectX만, 내장 그래픽 등)가 약 18~19%라서, 이 둘을 합치면 판정 가능 비율은 약 97%다. 나머지 약 3%는 "판정 불가"로 정직하게 보여준다.
- **성능 점수 출처는 쓸 수 있는 공개 데이터가 거의 없다.** PassMark는 "내 PC로 돌아가나" 류 사이트에는 데이터 사용권을 주지 않는다고 밝히고 있고, TechPowerUp·Geekbench·UserBenchmark도 상업 사이트 사용은 라이선스가 필요하거나 약관 확인이 필요하다. 그래서 **자체 등급표(티어)를 직접 만드는 안**을 추천한다. 교차 제조사 비교는 게임 요구 사양에 이미 적힌 "GTX 1060 또는 RX 480" 같은 동급 표기에서 뽑는다.
- **입력은 "직접 선택 + WebGL GPU 자동 입력 보조", 저장은 브라우저에만.** 서버로 사용자 사양을 보내지 않는다. 판정도 브라우저에서 한다.
- **예상 작업량은 약 8~12 작업일.** 가장 오래 걸리는 건 코드가 아니라 등급표(부품 목록·티어) 만드는 일이다.

## 1. 현재 데이터 조사

### 1-1. 저장 형태

`games` 표의 문자열 칸이 전부다. 파싱된 숫자 필드는 없다.

| 칸 | 내용 | 채워진 게임 (노출 643개 기준) |
|---|---|---|
| `min_spec` | 최소 사양 텍스트 | 642 |
| `recommended_spec` | 권장 사양 텍스트 | 561 |
| `storage_gb` | 저장 공간(GB), 최소 사양 텍스트에서만 추출 | 607 |

- 최소·권장 둘 다 있는 게임 560개, 최소만 82개, 권장만 1개, 둘 다 없는 게임 0개.
- 스팀 게임 617개 중 616개에 최소 사양이 있고, 비스팀(Epic 12·Battle.net 9·Riot 5)은 26개 모두 최소 사양이 있다.
- 형태는 `enrich-specs.mjs`가 스팀 `pc_requirements` HTML을 정리해서 `" / "`로 이어 붙인 텍스트다. 예:
  `운영 체제 *: Windows 10 64-bit / 프로세서: Intel Core i7-6700 or AMD Ryzen 5 1600 / 메모리: 12 GB RAM / 그래픽: GeForce GTX 1060 6 GB or Radeon RX 590 / 저장 공간: 62 GB 사용 가능 공간`
- 원문 HTML은 저장하지 않는다. 한 줄 길이는 중앙값 210자, 최대 1,282자.
- 상세 페이지에는 이미 `parseMinSpec`(`app/games/[id]/page.tsx`)이 `라벨: 값`으로 쪼개서 보여주는 접이식 "PC 사양" 카드가 있다. 이건 표시용이라 숫자·모델 인식은 하지 않는다.
- 참고(한계): `enrich-specs`는 `min_spec`이 비어 있는 게임만 채운다. 스팀에서 요구 사양이 바뀌어도 다시 받지 않는다.
- 참고: 권장 사양 텍스트는 맨 앞에 `권장:` 라벨 줄이 붙어서 온다. 한국어 상점 기준이라 칸 이름이 `프로세서/메모리/그래픽/저장 공간`이고, 일부 게임은 영어 칸 이름이 섞여 있다.

### 1-2. 표기 형식 분류 (50개 무작위 샘플 + 전체 642개 검증)

고정 시드로 최소 사양 50개를 뽑아 분류했다. 같은 규칙을 전체에도 돌려 비교했다.

| 칸 | 단일 모델 | A 또는 B 병기 | 모호·저사양 표기 | 판정 불가 | 칸 없음 |
|---|---|---|---|---|---|
| CPU (50개) | 27 | 14 | 7 (클럭·코어 수만 3, 그 밖의 모호 4) | - | 2 |
| GPU (50개) | 26 | 13 | 10 (VRAM·DX·내장만 5, 그 밖의 모호 5) | - | 1 |
| RAM (50개) | 숫자+단위 49 | - | - | - | 1 |

- CPU 표기: `Intel Core i7-6700`, `AMD Ryzen 5 1600`, `Core 2 Duo`, `Pentium 4 3.0GHz`, `2 GHz Dual Core`, `Intel or AMD Dual Core CPU`처럼 모델/세대/클럭이 섞여 있다.
- GPU 표기: `GeForce GTX 1060 6 GB`, `Radeon RX 590`, `Intel HD Graphics 630`, `Integrated`, `DirectX 10 호환`, `512MB`(VRAM만)가 섞여 있다.
- 232개 게임은 그래픽 칸에 "A 또는 B"(대안) 표기가 있다. 즉 최소 사양의 약 36%.
- RAM은 거의 `N GB RAM`이다. 오타(`8 MB RAM`, `1500 MB RAM`)가 드물게 있다.

### 1-3. 파싱 가능 비율 추정 (정규식 + 사전)

전체 노출 게임에 대해 `®·™` 같은 상표 기호를 지운 뒤 손으로 만든 정규식 몇 개로 돌린 결과다. 분류는 세 단계다.

- A = 부품 모델을 인식 (등급표에서 찾을 수 있음)
- B = 모델은 없지만 "저사양"으로 볼 수 있는 표기 (GHz만, DX만, 내장 등)
- C/없음 = 판정 불가 (`TBD`, `Yup`, 해상도만 적힌 칸, 칸이 아예 없음)

| | 최소 사양 (642개) | | | 권장 사양 (561개) | | |
|---|---|---|---|---|---|---|
| | A | B | C·없음 | A | B | C·없음 |
| CPU | 507 (79%) | 119 (19%) | 16 (2.5%) | 440 (78%) | 53 (9%) | 68 (12%) |
| GPU | 501 (78%) | 117 (18%) | 24 (3.7%) | 446 (80%) | 46 (8%) | 69 (12%) |

- CPU와 GPU를 모두 모델로 인식한 게임: 최소 455개(71%), 권장 416개(74%).
- 상표 기호 처리가 중요하다. 처음에는 `Ryzen™ 3 3100`, `Core™ i7`, `NVIDIA® GTX™ 1080 Ti`를 못 읽어서 73~76%였다. 기호를 지우자 78~79%로 올랐다.
- 권장 사양은 "C·없음"이 12%로 최소보다 높다. 권장 사양에 CPU·GPU 칸 자체가 없는 게임이 각각 65·60개 있기 때문이다. 이 경우는 "권장 판정 불가"로 표시하고 최소 사양 판정만 보여주면 된다.
- 주의: 이 수치는 "인식됐다"는 뜻이지 "정확히 읽었다"가 아니다. 정답 데이터와 비교한 검증은 아직 안 했다. 구현 첫 단계에서 100개를 사람이 대조해야 한다.

## 2. 성능 비교 데이터 출처 조사

판단 기준은 (1) 광고가 붙는 상업 사이트에서 써도 되는가, (2) 크롤링·재배포가 허용되는가, (3) 공개 데이터셋으로 받을 수 있는가다.

**확인 한계:** PassMark 약관 페이지와 TechPowerUp 페이지는 직접 열면 403이 나와서 원문은 못 읽었다. 아래 PassMark·TechPowerUp 내용은 검색 결과 요약과 공식 라이선스 안내 페이지를 근거로 한 것이다. 실제로 쓰기 전에 약관 원문을 반드시 확인한다.

| 출처 | 얻는 것 | 라이선스·약관 (확인한 범위) | 판단 |
|---|---|---|---|
| **PassMark** (CPU Mark, G3D Mark) | CPU·GPU 상대 점수 (가장 널리 쓰임) | 기관용 데이터 구독(라이선스)을 판다. "비교·순위·추천·'can I run it' 웹사이트"에는 데이터를 라이선스하지 않는다고 밝히고 있다. 공개 사이트에서 모은 점수도 같은 제한이 적용되고 구독 없이 재게시할 수 없다. 스크래퍼들은 "개인 용도만"이라고 명시. | 사용 불가 |
| **TechPowerUp GPU/CPU 데이터베이스** | GPU 사양, 상대 성능 | 기업용 라이선스·API를 판다. 연구·학생·학계용은 무료 API가 있다(출처 표기 권장). 상업·광고 사이트 사용은 별도 라이선스가 필요해 보임. | 라이선스 없이 사용 불가 (약관 원문 확인 필요) |
| **Blender Open Data** (opendata.blender.org) | Blender Cycles 렌더링 점수(CPU·GPU별 중앙값), 약 34만 건 | 사이트가 데이터를 "License-free — 저작권·특허·상표·영업비밀 규제 대상이 아님"으로 명시. JSON·CSV 다운로드와 매일 갱신되는 전체 스냅샷(zip) 제공. 정식 CC0 같은 라이선스 문구는 못 찾음. | 사용 가능 후보. 단, 렌더링 성능이라 게임 성능과 다르다 |
| **Steam Hardware & Software Survey** | 사용자들이 실제로 쓰는 GPU·CPU 점유율 (성능 점수 아님) | CSV로 받을 수 있고 월 1회 갱신. 재사용 약관 문구는 못 찾음. | 성능 출처는 아니고, "드롭다운에 어떤 부품을 넣을지" 고르는 참고로만 (아래 3-2) |
| **Geekbench Browser** | CPU 점수(및 GPU 컴퓨트) | 공개 API 없음. Pro 라이선스에 상업 사용 조건이 있음. 사이트 약관 전문은 확인 못 함. | 비추천 (약관 미확인) |
| **UserBenchmark** | CPU·GPU 상대 점수 | 약관 원문은 확인 못 함. 점수 산정 방식 논란이 커서 신뢰도 문제도 있음. | 비추천 |
| **Kaggle·GitHub의 "GPU 벤치마크" 데이터셋** | 위 사이트들에서 긁어 온 표 | 원본 사이트의 약관을 그대로 물려받는다. 상업 사용이 불분명. | 사용 금지 (출처가 PassMark·TechPowerUp이면 위와 같은 문제) |

### 2-1. 출처 없이 가능한 대안: 자체 등급표 (추천)

**아이디어:** 정확한 점수 대신 "비슷한 급"끼리 묶은 정수 티어를 직접 만든다. GPU는 약 15단계, CPU는 약 8단계면 충분하다(2026-10-05 조정: 처음 안은 1~40단계·부품 250개였다). 판정은 "내 티어 ≥ 요구 티어"만 본다. 게임 요구 사양 판정에는 이 정도 정밀도면 충분하다. (정확한 FPS를 예측하는 게 아니라 "제작사가 적은 기준"과 비교하는 일이기 때문)

1. 같은 제조사 안의 순서는 세대와 모델 번호로 거의 규칙적으로 정해진다.
   - NVIDIA: GTX 9 → 10 → 16 → RTX 20 → 30 → 40 → 50 시리즈, 같은 세대 안에서는 숫자·Ti·Super 순서.
   - AMD: HD 7000 → R9 200 → RX 400/500 → RX 5000 → 6000 → 7000 → 9000, Ryzen 세대.
   - Intel: Core 세대(i5-6500 = 6세대) + i3 < i5 < i7 < i9.
2. 제조사 사이의 대응(예: GTX 1060 ≈ RX 480)은 **게임 요구 사양 자체에서 뽑는다.** 제작사가 "GTX 1060 또는 RX 480"이라고 적은 것은 "동급"이라는 뜻이다. 현재 데이터에서 232개 게임이 대안 표기를 갖고 있어서 동급 쌍을 충분히 모을 수 있다. 이 쌍들을 모아 제조사 간 연결 고리로 쓰면 외부 점수가 없어도 교차 비교가 된다.
3. 수작업이 필요한 부분은 GPU 15단계·CPU 8단계의 등급표다. 부품마다 "세대·급 위치" 근거 한 줄을 달고, 벤치마크 사이트의 점수는 복사하지 않는다. Steam 하드웨어 설문의 상위 점유 목록과 Blender Open Data의 순위를 "내 표가 크게 어긋나지 않는지 점검하는 참고"로만 쓴다(값을 복사하지 않는다).
4. 노트북 GPU(Laptop GPU, Max-Q, Mobile)는 같은 이름의 데스크톱보다 한 단계 낮게, 별도 항목(`mobile: true`)으로 둔다.

## 3. 사용자 입력 방식 비교

### 3-1. 비교

| | 직접 선택 | WebGL GPU 자동 감지 | 조합 (추천) |
|---|---|---|---|
| 방식 | CPU·GPU 검색형 드롭다운 + RAM 선택 | 브라우저가 알려 주는 GPU 문자열(`UNMASKED_RENDERER_WEBGL`)을 읽음 | GPU는 자동으로 채워 두고 사용자가 확인·수정, CPU·RAM은 직접 선택 |
| 정확도 | 사용자가 모르면 못 고름 | GPU만 가능. CPU 모델·RAM은 못 읽음 | GPU 정확도 상승, CPU·RAM은 사용자 입력 |
| 입력 부담 | 큼 (특히 CPU 모델 모르는 사용자) | 거의 없음 | 중간 |
| 브라우저별 한계 | 없음 | 아래 표 | GPU 자동 감지가 안 되면 직접 선택으로 대체 |

### 3-2. WebGL 자동 감지의 한계

| 브라우저 | 동작 |
|---|---|
| Chrome·Edge 등 Chromium | 정확한 문자열을 준다 (예: `ANGLE (NVIDIA, NVIDIA GeForce RTX 3060 ... Direct3D11 ...)`). 문자열이 길어서 파싱 필요 |
| Firefox | 2021년부터 렌더러 문자열을 대략적인 구간으로 뭉개서 준다(기본값). 정확한 모델이 아닐 수 있음 |
| Safari | 상수(예: `Apple GPU`)를 준다. 정확한 모델을 알 수 없음 |
| Brave, Firefox의 지문 방지 모드 | 값을 일부러 바꾸거나 반올림 |
| 모바일·VM·원격 | 소프트웨어 렌더러(`SwiftShader`, `llvmpipe`) 또는 가상 GPU로 나올 수 있음 |

- 내장 그래픽과 외장 그래픽이 둘 다 있는 노트북은 OS가 고른 쪽 하나만 보인다.
- 그래서 "자동 감지 결과를 보여 주고 '맞나요?' 확인"하는 방식이 안전하다. 확신할 수 없으면(Safari·Firefox·소프트웨어 렌더러) 드롭다운으로 넘어간다.
- CPU와 RAM은 읽을 수 없다. `navigator.hardwareConcurrency`는 논리 코어 수만 주고, `navigator.deviceMemory`는 Chromium에서만 되고 최대 8로 잘려서 판정에 쓸 수 없다.

### 3-3. 입력값 저장 위치

**브라우저에만 저장한다 (localStorage).** 서버로 보내지 않는다.

- 하드웨어 조합은 개인을 식별하는 데 보조 단서가 될 수 있다(핑거프린팅). 서버에 쌓을 이유가 없다.
- 판정은 브라우저에서 한다. 게임별 파싱 결과(티어 숫자)를 전체 게임 목록과 같이 내려 보내면 서버가 사용자의 사양을 알 필요가 없다. 게임 목록(`/api/games/list`)에 게임당 숫자 몇 개가 늘어나는 정도라 용량 부담은 작다(643개 기준 수십 KB).
- 이미 개인정보처리방침 5항에 "브라우저 저장소에 닉네임·투표·목록 위치·비교 목록을 저장한다"는 설명이 있다. 여기에 "내 PC 사양"을 한 줄 추가하면 된다. 서버 저장이 없으니 새 수집 항목은 아니다.
- 로그인이 없는 사이트라 기기를 바꾸면 다시 입력해야 한다. 이건 감수한다. 주소로 공유하는 기능은 넣지 않는다(개인 사양이 주소에 남기 때문).

## 4. 추천안: 자체 등급표 + 브라우저 판정 + 직접 선택(GPU 자동 입력 보조)

### 4-1. 판정 규칙

- CPU 티어, GPU 티어, RAM 세 가지를 각각 비교한다. 저장 공간은 판정에 넣지 않고 표시만 한다(사용자가 입력하지 않는 값).
- 결과는 네 가지다.
  - **권장 사양 충족**: 권장 사양이 있고 세 항목이 모두 권장 이상.
  - **최소 사양 충족**: 세 항목이 모두 최소 이상.
  - **부족**: 하나라도 최소에 못 미침. 어느 항목이 부족한지 한 줄로 알려준다(예: "그래픽카드가 최소 사양보다 낮아요").
  - **판정 불가**: 최소 사양의 CPU 또는 GPU를 해석하지 못함. 억지로 판정하지 않는다.
- "A 또는 B" 대안은 **둘 중 낮은 티어**를 요구치로 쓴다(제작사가 둘 중 하나면 된다고 적었으므로).
- B 등급(GHz만, DX만, 내장 그래픽 등)은 가장 낮은 티어로 본다. 즉 거의 모든 PC가 충족.
- 표시는 텍스트 배지만 쓴다(아이콘·이모지 없음, 색은 기존 토큰).

### 4-2. 단계별 구현 계획

**1단계 — 데이터 기반 (약 3~4일, 화면 없음)** — 2026-10-05 확정안

1. `data/pc-spec/gpu-tiers.json`: GeForce GTX 400~RTX 50, Radeon HD 5000~RX 9000, Intel HD/UHD/Iris Xe/Arc를 세대와 급 기준 약 15단계로 분류. 항목마다 근거 한 줄. 노트북 GPU는 데스크톱보다 한 단계 낮게 별도 표기.
2. `data/pc-spec/cpu-tiers.json`: Intel Core(세대 × i3/i5/i7/i9), Ryzen(세대 × 3/5/7/9), 구형(Core 2, FX, Phenom 등)을 약 8단계로.
3. 등급표 검증: 게임 요구 사양의 "A 또는 B" 대안 표기(232개)에서 같은 줄에 나온 부품끼리 등급 차이가 2단계 이상이면 충돌 목록으로 보고한다. 등급표 수정은 보고를 본 뒤에 한다.
4. 파서 `app/lib/specParse.ts`(순수 함수)와 `scripts/parse-specs.mjs`(기본 미리보기, `--apply`일 때만 DB 쓰기): CPU 등급·GPU 등급·RAM GB·저장공간 GB와 `low_spec`·`confidence` 추출. 모델명이 없는 저사양 표기(내장 그래픽, DirectX만, GHz만)는 최저 등급 + `low_spec: true`. 상표 기호 제거 후 매칭.
5. 정확도 검증: 무작위 100개 게임을 파서와 Haiku가 각각 판정해 서로 다른 항목만 `docs/pc-spec-review.csv`로 뽑아 사람이 본다(AI 비용 $1 이하).
6. DB 마이그레이션 파일(`spec_parsed`, `spec_hash`)은 만들기만 하고 적용하지 않는다. `--apply`도 검수가 끝나기 전에는 실행하지 않는다.

**2단계 — DB·주간 작업 (약 2일)**

- DB 변경: `games.spec_parsed jsonb`(없으면 null)와 `games.spec_hash text` 두 칸 추가. 기존 `min_spec`·`recommended_spec`·`storage_gb`는 그대로 둔다(덮어쓰지 않음).
  - `spec_parsed` 모양 예: `{"v":1,"min":{"cpu":14,"gpu":18,"ram":8,"conf":"A"},"rec":{...}}`
  - 부품 표(`hw_parts`)는 DB에 두지 않고 파일로 시작해도 된다. 브라우저 드롭다운도 같은 JSON을 쓰기 때문이다.
- 스크립트 `scripts/parse-specs.mjs`: 파싱 결과가 없거나 `spec_hash`(사양 텍스트 해시)가 바뀐 게임만 처리한다. 이미 처리한 항목은 다시 처리하지 않고, 값이 있으면 덮어쓰지 않는다(`--apply` 없으면 미리보기). 기존 규칙(기록 테이블 삭제 금지, 데이터 채우기 스크립트의 멱등성)을 따른다.
- 주간 작업 연동: `scripts/run-steps.mjs`의 `weekly` 그룹에서 `enrich-specs` 다음, `fill-game-details` 근처에 `parse-specs --apply` 한 줄 추가. 새로 들어온 게임이 매주 자동으로 파싱된다.
- 요구 사양이 바뀌는 문제: 지금 `enrich-specs`는 한 번 채우면 갱신하지 않는다. 필요하면 월 1회 "인기 100개만 재수집 + 해시 비교" 단계를 따로 추가한다(이번 범위에서는 제외, 6번 항목 참고).
- AI 판정 비용(필요한 곳만):
  - AI가 필요한 건 정규식으로 안 풀리는 "C 등급"(`TBD`, 오타, 괄호 안에만 모델이 있는 문장)이다. 최소·권장을 합쳐 약 26칸이고, 모델이 괄호로 숨은 B 등급 일부를 더해도 최대 약 100칸이다. (칸 자체가 없는 경우는 AI도 못 채우므로 제외)
  - 호출당 입력 약 300토큰 + 출력 약 80토큰으로 잡으면 총 입력 약 3만·출력 약 1만 토큰. Haiku 4.5 가격(입력 $1·출력 $5 / 백만 토큰, 공시 가격 기준 추정이며 실행 전 재확인)으로 약 $0.1 안팎.
  - 등급표 초안 작성도 한 번에 약 250개 부품을 처리해 약 $0.1 미만.
  - 합계 약 $0.2~0.3. 웹 검색 도구는 쓰지 않는다. 프로젝트 규칙대로 실행 전에 예상 비용을 먼저 알리고, `scripts/` 폴더라서 `guardedClaudeFetch` 예외에 해당한다.
  - 새 게임은 매주 최대 수십 개라 주간 비용은 센트 단위다. AI 결과는 `spec_parsed`에 저장해 두고 같은 게임을 다시 호출하지 않는다.

**3단계 — 화면 (약 3일)**

1. 입력: "내 PC 설정"을 작은 패널로 만든다(드롭다운 검색형 CPU·GPU, RAM 선택, GPU 자동 입력 버튼). 상세 페이지에서 바로 열 수 있게 하고, 설정은 localStorage에 저장한다. GPU 자동 입력은 Chromium에서만 기본 노출하고, 나머지는 "자동 감지가 어려운 브라우저예요. 직접 골라 주세요" 문구.
2. 상세 페이지: 기존 접이식 "PC 사양" 카드(`app/games/[id]/page.tsx`의 `spec-columns`) 바로 위에 판정 한 줄을 넣는다. 예) "내 PC: 최소 사양 충족" + 항목별 충족/부족 한 줄 설명. 사양을 아직 안 넣었으면 "내 PC 사양을 넣으면 돌아가는지 알려드려요" 링크.
3. 개인정보처리방침 5항에 "내 PC 사양을 브라우저에만 저장" 문구 추가.

**4단계 — 검색 연동 (약 1~2일, 선택)**

- 필터 패널에 "내 PC에서 돌아가는 게임만" 토글, 결과 카드에 판정 배지. 게임 목록(`gameIndex`)에 `spec_parsed` 숫자만 포함해서 브라우저에서 필터한다.
- 1~3단계가 안정된 뒤에 한다.

**5단계 — 검수·정리 (약 1~2일)**

- 샘플 100개 정확도 재측정, 모바일·PC 확인, 설정이 없을 때의 빈 상태, 단위 테스트(`specParse`와 판정 규칙).

### 4-3. 예상 작업량

| 단계 | 내용 | 작업일 |
|---|---|---|
| 1 | 부품 목록·등급표·파서·정확도 검증 | 3~4 |
| 2 | DB 칸 추가, 파싱 스크립트, 주간 작업 연동, AI 보조 | 2 |
| 3 | 입력 패널, 상세 페이지 판정, 방침 문구 | 3 |
| 4 | 검색 필터·카드 배지 (선택) | 1~2 |
| 5 | 검수·테스트 | 1~2 |
| 합계 | | 약 8~12 (선택 단계 포함 시 상한) |

핵심 위험은 등급표의 품질이다. 코드는 단순하지만 티어가 틀리면 "돌아간다/안 돌아간다"가 틀린다. 그래서 첫 출시는 기능을 작게(상세 페이지 판정 한 줄만, 필터 없음) 내고 오판 신고를 받는 것을 권한다.

## 5. 위험과 미해결 질문

1. **라이선스 확인:** PassMark·TechPowerUp 약관 원문은 직접 확인하지 못했다. 이 설계는 두 곳을 쓰지 않는 방향이라 영향이 적다. Blender Open Data를 참고로 쓰는 경우에도 데이터를 그대로 담지 않고 점검용으로만 쓴다. "License-free"가 정식 CC0인지 불분명해서 필요하면 운영자(blender.org 문의 주소)에게 확인한다.
2. **오판 책임:** 이 판정은 "제작사가 적은 최소·권장 사양과 내 PC를 비교한 참고 정보"다. 화면에 "실제 성능과 다를 수 있어요" 문구를 둔다(가격 정보에 이미 비슷한 안내가 있음).
3. **VRAM·저장 공간·OS:** 1차에서는 판정하지 않는다. VRAM은 GPU 티어로 대충 반영되고, 저장 공간은 사용자가 입력하지 않으며, OS는 대부분 Windows다.
4. **스팀 요구 사양 갱신:** 한 번 채우면 갱신하지 않는 기존 동작은 그대로 둔다. 중요한 게임이 업데이트로 요구 사양이 크게 바뀌는 경우는 월 1회 재수집 단계로 따로 다룰 수 있다.
5. **비스팀 게임 26개:** 수동·AI로 채운 사양이라 표기가 더 불규칙할 수 있다. 파싱 정확도를 따로 확인한다.
6. **Apple 실리콘·모바일:** 게임이 Windows PC 기준이라 M1/M2 사용자는 "PC 사양 체커 대상이 아니에요"로 안내하고 판정하지 않는다.
